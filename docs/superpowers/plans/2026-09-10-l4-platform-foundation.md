# L4 课程自进化平台一期实施计划

> **执行方式：** 本计划是开发与验收清单，不是新的需求确认关卡。按任务顺序实现、测试、复核；发现与已确认设计冲突时才暂停。

**目标：** 在不破坏现有“押题宣传审计工作台”的前提下，交付一条可本地演示、可保存状态的 L4 纵向闭环：生产项目配置 → 题目诊断与候选池 → 节点放行 → 成品 → 成品后验反馈 → 规则归因与局部重跑。

**一期边界：** 使用脱敏样例和本地 JSON 存储验证产品结构。Feishu Base、PMO、CB、素材库和正式文档写入先以连接配置和待执行动作外显，不在一期使用真实业务数据或执行外部写入。

**技术路线：** Python 标准库 HTTP 服务 + 原生 HTML/CSS/JavaScript + JSON 文件存储 + `unittest`。新平台使用独立模块和入口，旧 `apps/exam_match_workbench.py` 保持可运行。

---

## 验收口径

1. 本地命令可以启动 L4 工作台，首页能看到生产项目、阶段、异常、AI 下一动作和规则版本。
2. 项目设置支持目标学生层、目标地区、考试类型/年份、计划产物、要解决的问题，以及各节点的四种介入策略。
3. 题目卡片独立显示“高频”“好题”“生产优先级”“内容健康”“视频生产覆盖”，不得把 P0 当成优先级。
4. 视频证据不足时可记录教师人工覆盖结论；有证据时显示证据层级、题目单元和覆盖得分点；“组合支撑但缺综合迁移”保持独立状态。
5. 自动运行只停在配置为“每次确认”的节点；“只看异常”只生成异常审核项；未阻塞对象继续运行。
6. 完全自动模式可以产出示例成品。老师只在成品处反馈时，系统能归因到上游节点、生成规则候选并只重跑受影响下游。
7. 项目内实验规则可自动进入回测；“发布为跨项目公共规则/公共 Skill”始终处于人工批准状态。
8. 测试覆盖优先级边界、介入策略、反馈归因、局部重跑和 API 主路径；旧工作台可编译并可启动。

## Task 2：实现优先级、放行和局部重跑规则

**文件：**

- 新建：`apps/l4_workbench/engine.py`
- 新建：`tests/test_l4_engine.py`

**实现：**

- `recommend_priority(question, project)`：先处理内容健康，再综合趋势、频次、覆盖缺口、目标学生收益、迁移价值和制作成本。
- 基础简单且对中等及以上学生增益低时默认 P3；高频易错或关键前置可升 P2。
- “组合支撑但缺综合迁移”默认 P2；高频、高分值且存在稳定卡点时可升 P1。
- `release_decision(stage, strategy, has_exception)`：实现四种介入策略。
- `affected_stages(feedback_category)`：将成品反馈归因到资料标准化、选题、母题、教案、逐字稿、分镜/成品，并返回最小下游重跑集合。

**测试：**

- P0 不可能出现在优先级结果中。
- 简单缺口不会因为“未覆盖”自动升为 P1/P2。
- 自动推进不等待，异常复核只拦截异常，每次确认会创建等待项。
- 逐字稿问题不会重跑资料标准化和选题。

**验证命令：**

```bash
python3 -m unittest tests.test_l4_engine -v
```

## Task 3：实现状态机与成品后验反馈闭环

**文件：**

- 新建：`apps/l4_workbench/service.py`
- 新建：`tests/test_l4_service.py`

**实现：**

- 创建生产运行并按阶段推进：标准化 → 诊断与选题 → 母题/教案 → 逐字稿 → 分镜与成品。
- 正常对象自动继续；证据缺失对象降级或进入异常队列，不阻断其他对象。
- 候选池支持题目/小问纳入、排除和理由；支持当前筛选批量通过，但风险项不参与。
- 成品反馈保存原反馈、AI 归因、规则候选、生效范围、重跑阶段和新版本。
- 公共规则发布操作只创建“待人工批准”的治理项，不自动发布。

**测试：**

- 全自动运行能到达成品完成。
- “教案每次确认”只停在教案阶段。
- 成品反馈后版本号增加，且只重跑受影响阶段。
- 公共发布不能被自动批准。

**验证命令：**

```bash
python3 -m unittest tests.test_l4_service -v
```

## Task 4：提供本地 API

**文件：**

- 新建：`apps/l4_workbench/web.py`
- 新建：`apps/l4_course_evolution_workbench.py`
- 新建：`tests/test_l4_api.py`

**接口：**

- `GET /api/state`：项目、题目、运行、审核、成品、规则摘要。
- `PATCH /api/project`：修改生产目标和介入策略。
- `PATCH /api/questions/{id}`：保存教研结论、纳入范围、人工覆盖结论与理由。
- `POST /api/runs`：创建并自动推进运行。
- `POST /api/reviews/batch-pass`：当前阶段/批次/筛选内批量通过。
- `POST /api/artifacts/{id}/feedback`：保存成品反馈并触发归因、规则候选与局部重跑。
- `POST /api/rules/{id}/request-publication`：创建公共发布审批请求。

**测试：**

- 主接口返回 JSON 且状态码正确。
- 非法字段返回 400，不写坏状态。
- 公共发布请求结果只能是 `待人工批准`。

**验证命令：**

```bash
python3 -m unittest tests.test_l4_api -v
```

## Task 5：实现一条可演示的产品界面

**文件：**

- 新建：`apps/l4_workbench/static/index.html`
- 新建：`apps/l4_workbench/static/styles.css`
- 新建：`apps/l4_workbench/static/app.js`

**页面：**

- 项目驾驶舱：项目目标、阶段漏斗、异常、AI 下一动作、规则版本、运行按钮。
- 题目资产与候选池：完整题图占位/来源、高频分子分母、好题理由、内容健康、覆盖证据、P1～P3、纳入小问、批量通过。
- 覆盖证据抽屉：视频证据级别、截图/逐字稿片段、题目单元、覆盖得分点、人工结论。
- 自动化设置：每个阶段四种策略，显示作用域和外部动作预授权状态。
- 成品与反馈：成品版本、反馈输入、AI 归因、规则候选、局部重跑日志。
- 规则进化：实验版本、基线/实验回测、变更摘要、当前作用域；公共发布按钮明确需要人工批准。

**交互验收：**

- 刷新页面后配置和反馈不丢失。
- 从“开始自动运行”到“成品反馈后重跑完成”不需要手工改 JSON。
- 所有状态都能看到原因和证据入口，不能只显示一个分数。
